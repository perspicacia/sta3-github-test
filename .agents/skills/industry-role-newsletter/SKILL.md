# Industry Role Newsletter

사용자가 선택한 산업과 직무를 교차해, 실제 취업 준비에 활용할 수 있는 최신 자료를 만든다.

## 시작 입력

다음 네 항목을 확인한다. 이전 대화에서 분명하면 다시 묻지 않는다.

- 산업
- 직무
- 기간: 기본값은 최근 30일, 자료가 부족하면 90일까지 확장하고 표시
- 저장 방식: 화면 요약, HTML 뉴스레터, Notion 데이터베이스 중 요청된 것

## 조사 원칙

검색은 아래 세 묶음으로 나눈다.

1. **산업 변화**: 시장, 고객 행동, 규제, 기술 도입, 기업의 데이터 활용
2. **직무 변화**: 실제 업무, 자주 요구되는 기술, 산출물, 협업 대상
3. **취업 실전**: 공식 학습 자료, 포트폴리오 주제, 면접·이력서에 활용할 근거

각 묶음에서 최근성만으로 자료를 고르지 않는다. 공식 기관·기업 채용 페이지·공식 기술 문서·원문 보고서를 우선하고, 게시일과 실제 사건일을 구분한다. 채용공고는 역할을 확인하는 보조 자료로만 사용한다.

자료마다 다음을 기록한다.

- 한 문장 핵심 요약
- 왜 지금 중요한지
- 해당 산업과 직무의 연결점
- 지원자가 이번 주에 할 수 있는 행동 1개
- 출처명, 원문 URL, 발행일, 수집일

같은 보도자료를 옮긴 기사나 URL이 같은 자료는 하나로 합친다. 확인할 수 없는 숫자와 합격 가능성은 추정하지 않는다.

## 뉴스레터 구성

자료를 많이 나열하지 말고 중요도 순으로 5~8개만 고른다.

1. 이번 호의 결론 1문장
2. 산업 신호 2~3개
3. 직무 신호 2~3개
4. 취업에 적용하는 방법
5. 이번 주 행동 체크리스트 3개
6. 출처와 조사 기준일

전문 용어는 처음 나올 때 쉬운 한국어 뜻을 붙인다. 사실, 해석, 추천 행동을 섞지 말고 구분한다.

## Notion 저장

사용자가 저장을 요청한 경우에만 외부 쓰기를 실행한다. 먼저 같은 이름의 데이터베이스를 검색하고, 있으면 스키마를 가져와 사용한다. 없으면 [Notion 스키마](references/notion-schema.md)를 읽고 사용자 지정 상위 페이지 아래에 새 데이터베이스를 만든다.

한 뉴스레터를 한 행으로 저장하지 말고, **출처 자료 한 건을 한 행**으로 저장한다. 저장 전 원문 URL로 중복을 확인하고, 같은 URL이 있으면 새 행을 만들지 말고 최신 요약·수집일을 갱신한다.

저장 후 생성 또는 갱신한 행 수, 건너뛴 중복 수, 데이터베이스 링크를 알려준다.

## 완료 확인

- 모든 핵심 주장에 원문 링크가 있는가
- 검색 기간과 조사 기준일을 표시했는가
- 산업과 직무 양쪽 자료가 포함됐는가
- 단순 채용공고 목록이 아닌 준비 행동이 있는가
- Notion에 저장했다면 실제 행을 다시 조회해 확인했는가
